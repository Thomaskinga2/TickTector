# Project structure

## How a feature is wired

```
page (app/) -> component (components/) -> service (lib/services/) -> API route (app/api/<feature>/) -> provider / data
                                                                                                    (lib/providers/, lib/data/)
```

- Pages and components call **service functions only**, never data files or `fetch` directly. (Exception: `townName()` reads the bundled Census town names so names never wait on the network.)
- Nothing shown is invented: data comes from `lib/data/` (generated by `scripts/`) or a live source in a provider.
- Unbuilt features say so (`501`, "Coming soon"). List open work with `grep -rn TODO app lib components`.

## Layout

```
app/
  page.tsx                  Home: town search, radar, and counties grouped by level (TownBrowser)
  area/[town]/              Town page: level color field, readout, modules (steps, ticks, sightings, map)
  map/  scan/  quest/       Risk map (Leaflet), camera scan, TickQuest
  forum/                    Sightings list, new sighting (sheet), post detail
  api/<feature>/route.ts    One route per feature: towns, risk, heatmap, species, alerts, scan, forum
  manifest.ts               PWA manifest
components/                 UI pieces named by what the user sees (TownBrowser, RiskReadout, ...)
  ui/                       Primitives: button, list (List/ListRow), segmented-control
  states.tsx                LoadingState, ErrorState, EmptyState, ComingSoon, Disclaimer
  page.tsx                  Page (large title + scroll-edge nav bar) and Section
  tab-bar.tsx               Floating glass tab bar
  town-browser.tsx          Home's town list and search
  risk-readout.tsx  town-module.tsx  meadow.tsx   Town page hero (with the meadow) and modules
  level-face.tsx  risk-badge.tsx   LevelFace and RiskBadge (level by face + word, never color alone)
  heatmap.tsx               Map wrapper; risk-map-canvas.tsx is the browser-only Leaflet map
  device-clock.tsx  format.ts   Device time; week range and relative dates
  risk-basis.tsx            "Why this level": the DPH and NWS numbers with source links
  source-links.tsx          SourceLink / SourceList: citations under modules
  fun-facts.tsx             "Did you know?": one cited fact a day (facts from /api/facts)
  tick.tsx  tick-icon.tsx    Tick the detective (mascot) and tick line symbols
scripts/                    build-map.mjs (Census → map + town list), build-risk-baseline.mjs (DPH), make-icons.mjs
lib/
  services/                 Client-side service functions, one file per area, all via getJson (http.ts)
  providers/                Server-side providers picked by env vars (geocoding, forum store)
  data/                     Generated, sourced data: ma-towns.json (Census), county-baseline.json (Mass. DPH fallback copy)
  providers/dph.ts          Newest Mass. DPH report from mass.gov (Table 1, checked row by row), bundled copy as fallback
  providers/risk.ts         Weekly risk: DPH baseline + NWS forecast, by a stated rule
  counties.ts               DPH county groups and labels
  mock-data.ts              Sourced static content (species, prevention steps), isDemoMode(), currentWeekOf()
  use-basemap.ts            Loads the vector map (public/map/massachusetts.json)
  features.ts               Feature flags: false shows "Coming soon"
  types.ts                  Shared types (the contract between frontend and backend)
  use-async.ts              Service call with loading / error / retry
  use-geolocation.ts        Browser location hook
  use-near-me.ts            Home's "Near you": asks for the location on load, IP-based town meanwhile
  photo.ts                  Resizes a picked photo to a JPEG (max 1600 px) before a sighting is posted
data/                       Real datasets go here
.kiro/                      Steering, hooks and specs (committed)
```

## Conventions
- File names use **kebab-case** (`risk-readout.tsx`); components are **PascalCase** named exports (`RiskReadout`).
- UI rules (tokens, type, materials, motion) are in `design.md`, loaded automatically for UI files.
- Each API route starts with a comment documenting its contract, e.g. `// GET /api/risk?town=amherst -> WeeklyRisk`.
- Shared types change only in `lib/types.ts`, and both sides adopt them in the same PR.
- Import with the `@/` alias from the project root.
